{% comment %} Gantt Chart =========== Renders the geometry produced by workspace.common.charts.gantt_chart as two inline SVGs side by side: a fixed-width gutter (row labels, group headers, progress) and a plot with a real pixel width. The caller wraps the whole thing in an overflow-x-auto container so a long span scrolls the plot only - the gutter is sticky, so the labels stay put while the bars scroll under them. Splitting the gutter out of the scrolling SVG is the point: a single SVG scrolled as a block took its row labels with it. Parameters: ----------- - chart: the dict returned by gantt_chart() - aria_label: accessible description of what the chart shows Activating a row (click or Enter) dispatches a bubbling `gantt-row` event whose detail carries `{ id }`; the caller listens for it and decides what opening a row means. Both SVGs carry the same per-row `` so either half of a row is clickable. The partial itself never names a module. Every coordinate in `chart` is a pre-formatted string and the template does no arithmetic on purpose - see the docstring in charts.py. Row/band/marker coordinates already include the gutter offset, so they draw correctly unmodified in the plot SVG's viewBox (which starts at x=gutter). The outer row is `w-max` and the plot SVG is `shrink-0`: without both, a flex child's `width` attribute is treated as a flex-basis, so a wide plot gets squeezed down to fit the scroll box instead of overflowing it, which is the one thing this layout exists to prevent. {% endcomment %}
