{% comment %} Sidebar "Preferences" trigger plus the panel it toggles. The panel is positioned against the sidebar header, not against the button, so it spans the header's width whatever else sits in the button row. The include site must therefore be inside a header that carries `relative` and the usual `px-3` padding - every module sidebar already looks like that, but a header missing `relative` silently anchors the panel to the page instead. Do not reach for daisyUI's `dropdown` here: it opens on `:focus-within` alone, which means it opens on Tab and never closes on a second click. Required context: - content: template path of the panel body, included as-is. - accent: full class of the heading icon's colour, e.g. "text-primary". Pass the complete class name, never a bare colour suffix - Tailwind's scanner keeps a class only when it appears as a literal string, and the include site is where it must appear. Optional context: - component: Alpine factory expression spread into the popover's scope, e.g. "filePreferences()". Omit it when the panel body reads state the surrounding component already exposes. - button_class: extra classes on the trigger, e.g. "hover:text-primary mr-1". - show_expr: x-show expression on the whole popover, e.g. "!collapsed", for sidebars that hide the trigger when collapsed. - close_on_event: name of a window event that also closes the panel, for a module that opens something else over the same sidebar. - panel_id: id of the panel, only needed on a page that includes the popover twice - the trigger points at it through aria-controls, so the two must not collide. {% endcomment %} {% firstof panel_id "preferences-panel" as pid %}
