{% comment %} Selection toolbar shared by the backlog and the all-tasks list: the bulk edits on the checked tasks. The including view wraps it in a `relative` row shown while `selected` (root projectBoard state) is non-empty, and may append its own controls after it (the backlog's send to board / sprint menus). Every control is gated on bulkCan(actionId): the action ids every selected task offers with bulk support, answered by POST /api/v1/projects/actions for the whole selection. Nothing is offered until that answer lands, and the handlers check the same list again. The assignee and label popovers are positioned against the row rather than their trigger so they never overflow the viewport on a phone; they reuse the task form pickers, with an add/remove toggle because the selection's tasks carry different values and "put Alice on these" must not strip whoever else was on them. {% endcomment %} selected {# Assign / unassign #}
