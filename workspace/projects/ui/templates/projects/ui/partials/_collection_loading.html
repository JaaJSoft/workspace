The caller wraps both in a relative box. The spinner rotates through a CSS transform, which the compositor keeps animating while the main thread is busy binding the new fragment - that is the only part of the wait the user would otherwise read as a freeze. It is sticky so a long backlog scrolled halfway down still shows it at mid-viewport rather than at the centre of a box that is off screen. The fade-in waits 200 ms so a filter that answers at once never flashes a half-drawn veil. The wait is a CSS transition-delay, not a timer: a timer set before the request cannot fire while the main thread is busy binding the fragment, the compositor runs the delay regardless. The veil never takes pointer events, so the page is not silently click-proof while the delay runs. {% endcomment %}
