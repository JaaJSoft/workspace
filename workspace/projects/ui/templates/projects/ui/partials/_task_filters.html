{% comment %} Shared board/backlog filter bar. Filtering is server-side: every change re-fetches the current view with the filters as query parameters (see applyFilters in board.js), so a filtered view is shareable by URL. The filter state lives on the root projectBoard component and is re-synced from the URL after each content swap. The bar itself is a single compact row (search + Filters button + Clear) so it degrades gracefully at any width; the pickers all live in a popover panel anchored under the bar. Filter changes swap #task-collection only, so the open panel keeps its DOM (and picker state) across them; the open flag (filtersPanelOpen) additionally lives on the root projectBoard component so the panel also survives the full content swaps of view navigations and SSE refreshes. Assignee and label are multi-value (repeated query params, OR'd server-side) and reuse the same picker components as the task form. Every active filter renders as a removable chip twice: inside the panel under its picker (the pickers themselves are search inputs and show nothing once a value is chosen), and on a row under the bar so the state stays readable while the panel is closed. {% endcomment %}
